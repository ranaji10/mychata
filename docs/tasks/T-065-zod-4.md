# T-065 zod 3 → 4

Owner: Claude (cloud session) · Status: review

Goal: move to zod 4 (tracker O-31; advisory GHSA-mrhx-c7xc-m3w5, memory use on oversized input in zod 3) without changing what any form accepts.

Non-goals: other dependencies (Dependabot PR #106 and its successors); new validation rules.

Files allowed: `package.json`, `bun.lock`, `src/lib/input-schemas.ts` (new), `src/lib/guest.functions.ts`, `src/lib/manual-qa.functions.ts`, `src/lib/task-translation.functions.ts`, `src/lib/t065.test.ts`, `docs/STATUS.md`, `docs/runbooks/dependency-updates.md`, tracker copies, this brief.

Invariants touched (AGENTS.md): none (no schema, no text).

## What changes

1. `zod` ^3.25.76 → ^4.6.7 (released 12 Oct 2026). Only our own server functions import zod; the router's build tools already used zod 4 internally.
2. The six server-function inputs move to `src/lib/input-schemas.ts`, unchanged in meaning: ids use `z.guid()` (zod 4's `z.uuid()` would refuse ids without RFC version bits, which zod 3's `uuid()` accepted), e-mail uses `z.email()`.
3. `src/lib/t065.test.ts` checks every input with what the forms send and what they must refuse (guest request form, house manual questions, document reading, manual rebuild, task translation), plus a 1 MB note refused in well under a second.

Forms in the app (React) don't use zod; nothing else changes for users.

## Acceptance

- `bun run check`; `bun audit` no longer lists zod.
- After publish: one manual question on a test cottage gets an answer; the organisation request form of a test cottage still sends (decline it afterwards).
